# 参考简历的版式规范

本技能根据用户提供的参考简历提取格式规律；复用布局与写作层级，不复用参考人物的姓名、联系方式、照片、学校、项目、公司或成绩。默认模板为 `reference-blue`，参数保存在 [reference-blue.json](../assets/reference-blue.json)。不同用户另给模板时，以新模板为准。

## 已观察到的格式与本技能实现

| 元素 | 参考格式 | 可复用实现 |
| --- | --- | --- |
| 纸张 | A4 竖版；左右约 12 mm，上下约 7 mm | A4，左右 12 mm，上下 10 mm，为跨软件重排留余量 |
| 姓名 | 22 pt，加粗，深蓝 `#244A68` | 保留字号、颜色、左对齐 |
| 个人信息 | 紧凑分行，多个信息项并排 | 电话、邮箱、城市、求职方向紧凑呈现，长链接单独换行 |
| 栏目 | 14 pt 深蓝加粗，细蓝分隔线 | 教育、技术栈、项目、实习等使用统一栏目样式与 0.75 pt 下边线 |
| 经历标题 | 项目／实习时间在左、名称居中区、角色或地点在右；教育为学校／专业学位／日期 | 用固定制表位和同宽 PDF 标题行；过长时改为自然换行，不挤压字体 |
| 经历正文 | 约 10 pt，描述背景、方法、职责与交付 | 默认 10.5 pt；完整短段落或多个有标题的条目，1.35 倍行距 |
| 技术栈 | 分组条目，组名强调，正文解释使用场景 | 使用“语言／框架／数据／工具”等有依据的分组，组名与关键技术局部加粗 |
| 页框 | 顶部与底部深蓝粗线 | Word 页眉页脚与 PDF 页边装饰线；不放入正文阅读顺序 |
| 图标／照片 | 参考包含栏目图标及个人照片 | 默认不复制参考图像；用户明确要求时只使用用户自己的照片或合法素材 |

这是参考格式的规范化版本，不是参考 DOCX 的逐像素复制。颜色、字号层级、对齐和正文密度是主要一致性标准；模板图标、照片和个人敏感字段不自动加入。

## 排版决策

默认工程岗位可采用“教育背景 → 技术栈 → 项目经历 → 实习经历 → 相关成果”的阅读顺序；更有说服力的实习可放在项目之前。不要无条件按技能旧版的教育→实习→项目→技能顺序排版。

技术名称不应全部堆在独立小标题里。每组技能写成一条有使用范围的陈述；项目和实习标题为一行元数据，其下才是具体贡献。避免把学校、公司、日期、角色拆成多个松散大段。项目没有日期时省略日期，不用“大学期间”充当唯一贡献条目。

正文需可选中、可编辑，强调使用真实字体样式，不用 Markdown `**` 原样输出。关键词强调只覆盖工具、模块、方法或成果，不能把整个段落变成粗体。分隔线、缩进和留白的节奏在所有栏目一致。

对于长项目名或长角色，标题行无法容纳时允许拆为两行，保持两种格式同样处理。先调整元数据换行，不缩小正文。过短的简历首先补问核心经历事实，而不是增加字号、重复毕业时间、添加空泛自评或拉大间距来填满页面。

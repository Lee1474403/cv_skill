# 生成器输入格式

输入 UTF-8 JSON；模板参考 [example-profile.json](../assets/example-profile.json)。示例人物、机构、经历和数据全部虚构，仅用于验证生成器；不得混入真实简历。

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `name` | 非空字符串 | 姓名或用户选择的展示名称；必需 |
| `language` | `zh` 或 `en` | 默认 `zh`，决定默认字体、求职意向标签 |
| `target_role` | 字符串 | 可省略，不由脚本猜测 |
| `contacts` | 字符串数组 | 可省略；如电话、邮箱、城市、完整公开链接 |
| `summary` | 字符串数组 | 可省略；建议 0–2 段 |
| `sections` | 非空数组 | 按实际展示顺序排列；至少含一条教育或经历信息 |
| `sections[].kind` | 枚举字符串 | `education`、`experience`、`projects`、`skills`、`awards`、`campus`、`certifications`、`publications`、`other` |
| `sections[].title` | 非空字符串 | 如“教育背景”“实习经历”，支持自定义语言 |
| `sections[].entries` | 非空对象数组 | 展示顺序由撰写者确定，脚本不擅自排序 |
| `entries[].heading` | 非空字符串 | 学校/公司/项目/技能组名称 |
| `entries[].detail` | 字符串 | 可省略；学位与专业、岗位、项目性质等 |
| `entries[].date` | 字符串 | 可省略；采用下面支持的日期格式 |
| `entries[].location` | 字符串 | 可省略；城市或远程 |
| `entries[].bullets` | 字符串数组 | 可省略；每项是一条正文，不含手打列表前缀 |
| `entries[].paragraphs` | 字符串数组 | 可省略；完整经历短段落，在贡献条目前展示 |
| `entries[].emphasis` | 字符串数组 | 可省略；需要局部加粗的短语，必须是该条目实际展示文字的原样子串 |

仅允许表内字段。空字符串和空数组表示可选内容缺失；空栏目或条目不允许。换行写成单独条目，字符串内禁止换行、制表符和控制字符。

日期支持 `YYYY`、`YYYY.MM`、`YYYY - YYYY`、`YYYY.MM - YYYY.MM`；结束时间可写 `至今` 或 `Present`；可添加后缀 `（预计）` 或 ` (Expected)`。月数必须为 01–12，起止时间不能倒置，不混用年度和月度精度。不知道月份时使用年度精度，不猜月份。示例：`2022.09 - 2026.06（预计）`。时间冲突和未来任职真实性仍需人工检查。

生成器不会证明内容真实、识别所有敏感数据或判断岗位相关性。这些工作由使用技能的助手完成。生成前清理未确认条目，不能靠脚本补事实。

`paragraphs` 适合参考简历中的完整技术描述；`bullets` 适合按模块拆分贡献；二者可以同时使用，但不重复表达。日期存在时，参考版式的教育按“学校／专业与学位／时间”，项目与实习按“时间／名称／角色或地点”形成标题行。`skills` 的每个条目排成“组名：具体能力说明”，不拆成多个粗体大标题。未知日期仍省略，不伪造。

项目和实习正文过短时会阻止默认导出，要求补问。`--review-only` 输出待完善的条目；`--allow-sparse` 仅用于用户明确选择的事实受限稿。格式有效不代表内容已完善。

最小输入：

```json
{
  "name": "用户提供的展示名称",
  "language": "zh",
  "sections": [
    {
      "kind": "education",
      "title": "教育背景",
      "entries": [
        {"heading": "用户提供的学校", "detail": "用户提供的专业与学位"}
      ]
    }
  ]
}
```

上面的文字解释字段用途，实际生成时必须替换为真实信息；这是格式示例，不是可投递履历。
